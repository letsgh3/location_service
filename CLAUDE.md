# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Monorepo for a Polish real-estate listings app. Each deployable part is a self-contained service under `services/` with its own dependencies, tests and README; services talk only over HTTP and must not import code from each other. Requirements docs (`docs/*.md`), UI strings, test names and most code comments are in Polish.

- `services/backend/`: FastAPI, async SQLAlchemy 2.0 (aiosqlite), Alembic, JWT auth. It has its own `CLAUDE.md` and `.claude/settings.json` with hooks, so read that file before changing backend code.
- `services/frontend/`: React 19 and Vite 7 (plain JS, no TypeScript, no linter, no unit tests).
- `services/e2e/`: pytest and Playwright (Python) browser tests that start the backend and frontend themselves.

## Commands

From the repo root:

```bash
./install.sh [--with-e2e]   # backend venv + `pip install -e ".[dev]"` + .env with generated SECRET_KEY + migrations; frontend `npm ci`; optionally e2e venv + Chromium
./start.sh                  # migrate DB, then backend :8000 and frontend :5173 (override with BACKEND_PORT / FRONTEND_PORT)
```

Backend (`cd services/backend && source venv/bin/activate`):

```bash
pytest -q                                          # all tests (in-memory SQLite)
pytest -q tests/api/test_locations.py::test_name   # single test
alembic revision --autogenerate -m "message"       # after changing sql_app/models.py
python -m sql_app.init_db                          # = alembic upgrade head
```

Frontend (`cd services/frontend`): `npm run dev`, `npm run build`. The build is the only automated check for the frontend.

E2E (`cd services/e2e && source venv/bin/activate`):

```bash
pytest -q                    # headless; starts its own backend on :8001 (temp SQLite DB) and Vite on :5174
pytest -q -k login --headed  # subset, visible browser
E2E_BASE_URL=http://127.0.0.1:5173 pytest -q   # run against an already running app (creates real data)
```

## Cross-service architecture

- **No CORS on the backend.** The frontend calls `/api/*` and the Vite dev server proxies it to the backend with the `/api` prefix stripped (`vite.config.js`, target from `BACKEND_URL`). E2E tests use the same proxy. Backend routes are defined without `/api`.
- **Auth flow.** `POST /auth/register` takes JSON. `POST /auth/login` uses `OAuth2PasswordRequestForm`, so it takes form-encoded `username`/`password`, not JSON. It returns a JWT (HS256, `SECRET_KEY` from `services/backend/.env`). The frontend keeps the token in `localStorage` (`accessToken`) and on a 401 clears it and dispatches the `auth:expired` window event, which `App` listens for. Location write endpoints (POST/PATCH/DELETE) require the token; reads do not.
- **API client.** All frontend HTTP calls go through `request()` in `services/frontend/src/api.js`. Add new endpoints there.
- **E2E conventions.** Use accessible locators (`get_by_label`, `get_by_role`, `get_by_placeholder`) rather than CSS selectors. Seed data through the `api` fixture unless creation is the behaviour under test. Use unique emails and city names, because the DB is shared across a test session.

## Schema and generated docs

- Model changes in `services/backend/sql_app/models.py` must ship with an Alembic migration. The PR review checks for this.
- `docs/schema.md` is generated by `services/backend/scripts/gen_model_docs.py`, so don't edit it by hand. The backend's Claude Code `PostToolUse` hook regenerates it after edits to `models.py`, and its `Stop` hook runs `pytest -q` and blocks on red tests. These hooks apply only when Claude Code is started from `services/backend/`.

## CI and agent tooling

- `.github/workflows/tests.yml` runs backend `pytest -q` (Python 3.11) on every push and PR. Frontend and e2e are not run in CI.
- `.github/workflows/agent-review.yml` runs an AI review of each PR with the Codex CLI, using `.agent/review-prompt.md` and `.agent/review-schema.json` (secret `OPENAI_API_KEY`). It looks for regressions: logic bugs, bad queries, missing migrations, API contract breaks, security.
- `.claude/agents/commit-planner.md` is a planning-only subagent that writes Multi-Commit Plans (conventional commits, per-service verification command, line budget) to `.agent/plans/<slug>.md`. See `.agent/plans/listings.md` for an example. When implementing such a plan, follow its order and scope and run the listed verification after each commit.
